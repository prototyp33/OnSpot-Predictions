## Core Tables

### models

**Description**: Stores metadata about machine learning models used for parking predictions.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the model |
| model_type | text | Type of the model (e.g., "random_forest", "gradient_boosting") |
| version | text | Version identifier of the model |
| training_date | timestamp | Date and time when the model was trained |
| location_id | uuid | Reference to location the model is trained for (null if global) |
| parameters | jsonb | Model hyperparameters and configuration |
| metrics | jsonb | Performance metrics of the model from training/validation |
| status | text | Current status of the model (e.g., "active", "archived") |
| created_at | timestamp | Timestamp when the record was created |
| updated_at | timestamp | Timestamp when the record was last updated |

**Relationships**:
- One model can have many predictions
- One model can have many drift_analysis records
- One model can have many retraining_events

### predictions

**Description**: Stores parking occupancy predictions generated by the models.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the prediction |
| model_id | uuid | Foreign key reference to the model that generated this prediction |
| location_id | uuid | Identifier for the parking location |
| timestamp | timestamp | Date and time for which the prediction is made |
| predicted_occupancy | numeric | Predicted parking occupancy (can be percentage or count) |
| prediction_interval_lower | numeric | Lower bound of the prediction interval |
| prediction_interval_upper | numeric | Upper bound of the prediction interval |
| features_used | jsonb | Features and their values used to generate this prediction |
| actual_occupancy | numeric | Actual observed occupancy (updated after the fact) |
| created_at | timestamp | Timestamp when the prediction was generated |

**Relationships**:
- Many predictions belong to one model
- Predictions are related to locations (not a formal foreign key)

### raw_parking_data

**Description**: Stores raw parking data as collected from sensors and other sources before any processing.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the data point |
| location_id | uuid | Identifier for the parking location |
| timestamp | timestamp | Date and time when the data was collected |
| occupancy | numeric | Raw occupancy count or percentage as reported by sensors |
| data_source | text | Source of the data (e.g., "sensor", "manual_count") |
| raw_payload | jsonb | Complete raw data as received from the source |
| created_at | timestamp | Timestamp when the record was created |

**Relationships**:
- Raw data is processed into cleaned_parking_data

### cleaned_parking_data

**Description**: Stores parking data after cleaning and validation steps.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the data point |
| raw_data_id | uuid | Reference to the original raw data |
| location_id | uuid | Identifier for the parking location |
| timestamp | timestamp | Date and time the data represents |
| occupancy | numeric | Cleaned and validated occupancy value |
| is_anomaly | boolean | Flag indicating if the data point was identified as an anomaly |
| cleaning_notes | text | Notes on any cleaning operations performed |
| created_at | timestamp | Timestamp when the record was created |

**Relationships**:
- Many cleaned records can reference one raw data record
- Cleaned data is used to create feature_engineered_data

### feature_engineered_data

**Description**: Stores data with engineered features ready for machine learning models.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the data point |
| cleaned_data_id | uuid | Reference to the cleaned data |
| location_id | uuid | Identifier for the parking location |
| timestamp | timestamp | Date and time the data represents |
| occupancy | numeric | Target variable - parking occupancy |
| day_of_week | integer | Day of week (0-6, where 0 is Monday) |
| hour_of_day | integer | Hour of day (0-23) |
| is_weekend | boolean | Whether the day is a weekend |
| is_holiday | boolean | Whether the day is a public holiday |
| weather_temperature | numeric | Temperature at the time |
| weather_precipitation | numeric | Precipitation amount at the time |
| weather_conditions | text | General weather conditions (e.g., "Clear", "Rain") |
| events_nearby | jsonb | Information about nearby events that might affect parking |
| time_features | jsonb | Additional derived time features |
| lag_features | jsonb | Lagged values of occupancy (previous hours/days) |
| created_at | timestamp | Timestamp when the record was created |

**Relationships**:
- Many feature records can reference one cleaned data record
- Feature engineered data is used for model training and predictions

## Monitoring Tables

### drift_analysis

**Description**: Tracks model drift over time to identify when models need retraining.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the drift analysis |
| model_id | uuid | Foreign key reference to the model being analyzed |
| timestamp | timestamp | When the drift analysis was performed |
| baseline_timestamp | timestamp | Reference timestamp for the baseline distribution |
| feature_drift_scores | jsonb | Drift scores for individual features |
| overall_drift_score | numeric | Aggregated drift score |
| drift_detected | boolean | Whether significant drift was detected |
| recommended_action | text | Recommended action based on drift analysis |
| created_at | timestamp | Timestamp when the record was created |

**Relationships**:
- Many drift analyses belong to one model

### retraining_events

**Description**: Records model retraining events and their outcomes.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the retraining event |
| model_id | uuid | Foreign key reference to the original model |
| new_model_id | uuid | Foreign key reference to the newly trained model (if successful) |
| timestamp | timestamp | When the retraining was performed |
| trigger | text | What triggered the retraining (e.g., "scheduled", "drift_detected") |
| success | boolean | Whether the retraining was successful |
| performance_change | numeric | Percentage change in model performance |
| notes | text | Additional notes about the retraining process |
| created_at | timestamp | Timestamp when the record was created |

**Relationships**:
- Many retraining events belong to one model
- Successful retraining events create new model records

### system_health

**Description**: Monitors the health and performance of the prediction system.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the health record |
| timestamp | timestamp | When the health check was performed |
| component | text | System component being monitored |
| status | text | Status of the component (e.g., "healthy", "degraded", "down") |
| response_time_ms | integer | Response time in milliseconds (if applicable) |
| error_count | integer | Number of errors encountered |
| warning_count | integer | Number of warnings encountered |
| metrics | jsonb | Additional performance metrics specific to the component |
| notes | text | Additional context or notes |
| created_at | timestamp | Timestamp when the record was created |

## Business Intelligence Tables

### business_metrics

**Description**: Stores business performance metrics for analytical and reporting purposes.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the metric |
| timestamp | timestamp | Date and time the metric represents |
| metric_name | text | Name of the business metric |
| metric_value | numeric | Value of the business metric |
| category | text | Business category the metric belongs to |
| dimensions | jsonb | Additional dimensions for multi-dimensional analysis |
| notes | text | Any additional context or notes |
| created_at | timestamp | Timestamp when the record was created |

### location_metrics

**Description**: Stores performance metrics specific to parking locations.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the location metric |
| location_id | uuid | Identifier for the parking location |
| date | date | Date the metrics represent |
| average_occupancy | numeric | Average occupancy for the day |
| peak_occupancy | numeric | Peak occupancy for the day |
| peak_time | time | Time when peak occupancy occurred |
| total_vehicles | integer | Estimated total vehicles using the location |
| prediction_accuracy | numeric | Accuracy of predictions for this location and day |
| revenue | numeric | Estimated or actual revenue generated (if applicable) |
| created_at | timestamp | Timestamp when the record was created |

**Relationships**:
- Location metrics are related to specific parking locations

## A/B Testing Tables

### ab_tests

**Description**: Stores information about A/B tests run on the prediction system.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the A/B test |
| name | text | Name of the A/B test |
| description | text | Detailed description of what is being tested |
| status | text | Current status of the test (e.g., "planned", "running", "completed") |
| start_date | date | Date when the test started |
| end_date | date | Date when the test ended or is scheduled to end |
| hypothesis | text | The hypothesis being tested |
| success_criteria | jsonb | Criteria for determining test success |
| created_at | timestamp | Timestamp when the record was created |
| updated_at | timestamp | Timestamp when the record was last updated |

**Relationships**:
- One A/B test can have multiple test variants

### test_variants

**Description**: Stores the different variants in an A/B test.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the variant |
| test_id | uuid | Foreign key reference to the A/B test |
| name | text | Name of the variant (e.g., "A", "B", "Control") |
| description | text | Detailed description of the variant |
| configuration | jsonb | Technical configuration specific to this variant |
| allocation_percentage | numeric | Percentage of traffic allocated to this variant |
| created_at | timestamp | Timestamp when the record was created |
| updated_at | timestamp | Timestamp when the record was last updated |

**Relationships**:
- Many variants belong to one A/B test
- One variant can have many daily metrics

### test_daily_metrics

**Description**: Stores daily performance metrics for each test variant.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the daily metric |
| variant_id | uuid | Foreign key reference to the test variant |
| date | date | Date the metrics represent |
| impressions | integer | Number of impressions or exposures for the variant |
| clicks | integer | Number of clicks or interactions |
| conversions | integer | Number of conversions or desired actions |
| revenue | numeric | Revenue generated by this variant on this day |
| custom_metrics | jsonb | Additional custom metrics specific to the test |
| created_at | timestamp | Timestamp when the record was created |

**Relationships**:
- Many daily metrics belong to one test variant

## User Management Tables

### users

**Description**: Stores user account information.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| id | uuid | Primary key, unique identifier for the user |
| email | text | User's email address (must be unique) |
| first_name | text | User's first name |
| last_name | text | User's last name |
| created_at | timestamp | Timestamp when the user account was created |
| updated_at | timestamp | Timestamp when the user account was last updated |

**Relationships**:
- One user can have multiple roles through user_roles table

### user_roles

**Description**: Stores role assignments for users in the system.

| Column Name | Data Type | Description |
|-------------|-----------|-------------|
| user_id | uuid | Foreign key reference to the user |
| role | text | Role assigned to the user (e.g., "admin", "analyst", "viewer") |
| assigned_at | timestamp | When the role was assigned to the user |
| assigned_by | uuid | User who assigned this role |
| created_at | timestamp | Timestamp when the record was created |

**Relationships**:
- Many role assignments can belong to one user
- Role assignments may reference the user who assigned the role
